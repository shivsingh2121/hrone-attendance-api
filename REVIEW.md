# REVIEW.md

Review of the starter `app/main.py` (line numbers refer to the starter as received, commit "Initial candidate kit").
Examples assume shift 09:30-18:30 unless stated; times are IST.

| # | Where (function / line) | What is wrong | How you'd notice it (test, input, or symptom) | How you fixed it |

| 1 | module, l.22-23 | Connection details hard-coded as fallbacks (`localhost`, `attendance_db`). A missing env var silently connects to the wrong database instead of failing. | Start without `MONGO_URI` set: app starts and talks to a local DB nobody intended. | Read `MONGO_URI` / `MONGO_DB` from the environment (`.env` only as fallback, `override=False`); fail at startup if they are missing. |
| 2 | module, l.22 | `MongoClient` without `tz_aware=True` returns naive datetimes, so every comparison with an aware datetime breaks or silently assumes local time. | Read a seeded `punch_in` and subtract an aware IST datetime: `TypeError`, or a 5:30 h shift when compared as local time. | `MongoClient(..., tz_aware=True)`; all instants are aware UTC internally, IST only for calendar maths. |

## Looked at and decided it is not a defect

- `load_dotenv()` defaults to `override=False`, so real environment variables already win over `.env`. Kept, made explicit.
- `date` stored as a `YYYY-MM-DD` string: zero-padded ISO dates sort and compare correctly as strings, so range queries on strings are right.
- `IST = timezone(timedelta(hours=5, minutes=30))`: India has no daylight saving time, so a fixed offset is correct.
- Synchronous `def` endpoints with PyMongo: FastAPI runs them in a thread pool and `MongoClient` is thread-safe, so parallel requests are handled correctly. Motor is not required.
- Punch-in initialises `history` to `[]`, `overtime_minutes` to 0 and `half_day` to false: matches the contract.
